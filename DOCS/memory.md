# 1. Project Overview

## Project Name
**NETRA-X**

## Project Type
AI-Powered Mine Safety and Rescue Rover

## Main Objective
Build a rover that can enter hazardous underground coal mine areas before human rescue teams, collect real-time environmental data, detect possible survivors, map underground tunnels, identify hazards, recommend safer routes, and send all mission information to a surface control team.

## Core Value Proposition
NETRA-X should help rescue teams answer:

- Is the mine area safe to enter?
- Where is the rover?
- Where are the hazards?
- Is there a possible trapped worker?
- Which route is safer?
- Is communication still reliable?
- Is the rover healthy and able to return?

---

# 2. Problem Statement

Underground coal mines can face:

- Methane and toxic gas leaks
- Carbon monoxide exposure
- Low oxygen
- H₂S presence
- High temperature and humidity
- Flooding and water accumulation
- Tunnel collapse and blocked passages
- Poor visibility
- Communication failure
- Difficulty locating trapped workers
- Delayed rescue decisions due to lack of real-time information

Human rescuers often enter with incomplete information, increasing risk and response time.

NETRA-X is designed to reduce this uncertainty by performing pre-entry reconnaissance and transmitting real-time underground information.

# 4. Core Innovations

## 4.1 AI-Based Survivor Detection
Uses RGB camera + YOLO person detection, with thermal confirmation.

Important:
- YOLO detects a **person**
- It does not directly know if the person is trapped or medically alive
- A detected person is treated as a **potential survivor**

---

## 4.2 AI-Based Hazard Mapping
SLAM creates the mine map.

Hazard mapping overlays environmental and sensor risks onto the map.

Examples:
- Safe zone
- Gas hazard
- Flood area
- Obstacle
- Weak communication zone
- Potential survivor location

Important:
- SLAM is not the AI model
- Hazard mapping is generated by combining map coordinates with sensor and perception data

---

## 4.3 Integrated Multi-Sensor System
Combines:
- RGB camera
- Thermal camera
- Gas sensors
- LiDAR
- IMU
- Environmental sensors
- Communication strength
- Battery information

Goal:
Avoid relying on a single sensor for important decisions.

---

## 4.4 Self-Recovery Mechanism
If the rover is stuck:

1. Detect lack of movement
2. Stop
3. Reverse
4. Turn
5. Re-plan route
6. Retry
7. Alert operator if recovery fails

Possible stuck detection:
- Motor commanded to move
- Wheel encoder reports motion
- IMU/LiDAR shows no real displacement

---

## 4.5 Pre-Entry Ghost Scan
A pre-entry reconnaissance mode where the rover:

- Enters before human rescuers
- Maps the area
- Detects hazards
- Checks environmental conditions
- Searches for potential survivors
- Builds a risk-aware underground map

---

## 4.6 Risk-Aware Autonomous Exploration
Instead of only asking:

> “How do I go from A to B?”

NETRA-X asks:

> “Given the current mine conditions, where should I go next?”

The planner evaluates candidate routes using:

- Gas risk
- Obstacle risk
- Temperature/environment risk
- Flood risk
- Communication quality
- Battery/return risk
- Distance
- Survivor probability
- Exploration value

Example:

```text
LEFT TUNNEL
Mission Risk: 76 / 100
High gas + weak communication

RIGHT TUNNEL
Mission Risk: 24 / 100
Stable environment + strong communication

Recommended Route → RIGHT
```

Current MVP strategy:
**Deterministic weighted risk scoring + risk-aware A\* path planning**

Future enhancement:
Machine learning could learn better risk weights from real mission data.

# 5. AI and Software Architecture

## 5.1 Main AI Model
**YOLOv8n**

Purpose:
- Detect person class from RGB camera frames

Why YOLOv8n:
- Lightweight
- Fast
- Suitable for edge systems
- Good speed/accuracy tradeoff

Current model strategy:
- Start with pretrained YOLO
- Use transfer learning later for mine-specific fine-tuning

---

## 5.2 Model Training Plan

### Starting Point
Pretrained YOLO model.

### Fine-Tuning Dataset
Mine-like images containing:

- Workers
- People lying down
- Partial visibility
- Low light
- Dust
- Smoke
- Occlusion
- Different viewing distances
- Different body orientations

### Annotation
Use bounding boxes around people.

Possible tools:
- Roboflow
- CVAT
- LabelImg

### Data Split
Example:

```text
70% Training
20% Validation
10% Testing
```

or:

```text
80% Training
10% Validation
10% Testing
```

### Augmentation
Possible augmentations:

- Brightness reduction
- Contrast changes
- Blur
- Noise
- Rotation
- Cropping
- Occlusion
- Scale changes
- Haze/smoke simulation

### Evaluation
Track:

- Precision
- Recall
- mAP
- False positives
- False negatives

Important:
**Recall is especially important because missing a survivor is more dangerous than generating an extra warning.**

# 7. Thermal Processing

Thermal imaging is used as a confirmation layer.

MVP approach:
- Temperature-based region detection
- Heat-signature analysis
- Compare with RGB/YOLO detection

Example:

```text
YOLO Person = YES
Thermal Signature = YES
        ↓
High Confidence Potential Survivor
```

Thermal processing does not need a separate neural network in the MVP.

---

# 8. Sensor Fusion

Sensor fusion means combining several independent observations before making a decision.

Example:

```text
YOLO Person Detection   +50
Thermal Confirmation    +35
Audio Distress Signal   +15
```

Example result:

```text
0–40   Low Confidence
41–69  Possible Human
70+    High Confidence
```

Current approach:
**Weighted deterministic sensor fusion**

Reason:
- Easy to understand
- Easy to validate
- Suitable for prototype
- Does not require another trained model

# 9. Hazard Detection

Important distinction:

**Physical sensors detect gas. AI does not physically detect gas.**

Example:

```text
Methane Sensor
      ↓
CH₄ Reading
      ↓
Hazard Logic
      ↓
SAFE / WARNING / DANGER
```

Current hazard detection approach:
- Sensor thresholds
- Rule-based classification
- Risk scoring

Possible monitored values:
- CH₄
- CO
- O₂
- H₂S
- Temperature
- Humidity
- Water level

Prototype thresholds should be treated as demonstration values.

Real deployment would require:
- Industrial calibrated sensors
- Mine-safety standards
- Field validation
- Safety certification

# 13. Navigation

## A* Path Planning
Used to calculate a route through the map.

Risk-aware version uses different costs:

```text
Safe Cell         Cost 1
Warning Area      Cost 5
High Gas Area     Cost 50
Flood Area        Cost 100
Wall              Not Traversable
```

The planner should choose:
**lowest-risk viable route**, not simply shortest distance.

Low-risk environment.

Medium risk.

## Red — Human Authorization Required

# 28. Important Presentation / Judge Answers

## Which AI model?
**YOLOv8n for person detection.**

## Pretrained or trained?
**Pretrained initially; fine-tuned later with mine-specific data.**

## Why YOLOv8n?
Lightweight, faster, lower compute, good for edge systems.

## Does AI detect methane?
No. Physical gas sensors detect methane.

## What does OpenCV do?
Image capture, preprocessing, enhancement, visualization, and video handling.

## What does SLAM do?
Builds the mine map and localizes the rover without GPS.

## What does ROS 2 do?
Connects robotics software modules.

## What is sensor fusion?
Combining multiple independent sensor observations to improve reliability.

## What is hazard detection?
Converting physical sensor readings into safe/warning/danger classifications.

## What is risk-aware navigation?
Choosing a lower-risk route instead of simply the shortest route.

## What if AI fails?
Manual camera, thermal sensing, environmental sensors, fail-safe logic, and operator control remain available.

## Is the rover fully autonomous?
Current MVP should be described as **semi-autonomous with manual override**.

# 29. Decision Log

**Current:** YOLOv8n
